# 🔍 EVIDENCE_CHECK: รายงานผลการตรวจสอบคำกล่าวอ้างกับโค้ดจริง (Code-Level Fact Verification)

เอกสารนี้ตรวจสอบคำกล่าวอ้างทางเทคนิคสำคัญ 6 ประเด็นของระบบ `ชวกม.2` เทียบกับโค้ดภาษา Python และไฟล์ข้อมูลที่รันอยู่จริง โดยจำแนกเป็น 3 สถานะอย่างตรงไปตรงมา:
- 🟢 **พบหลักฐานรองรับ (Verified by Code):** มีฟังก์ชันหรืออัลกอริทึมทำงานจริงในสคริปต์
- 🟡 **พบเพียงข้อความกล่าวอ้าง / กึ่งทำงานด้วยมนุษย์ (Claimed / Semi-Automated / Hardcoded):** มีผลลัพธ์ในรายงานแต่โค้ดเป็นการกำหนดค่าล่วงหน้า (Pre-baked / Hardcoded) หรือพึ่งพาการจัดเตรียมโดยมนุษย์
- ⚪ **ยังตรวจไม่ได้ (Unverifiable):** ขาดข้อมูลหรือไฟล์บันทึกการรันที่สามารถยืนยันได้

## 1. ตารางสรุปผลการตรวจสอบทั้ง 6 ประเด็น

| หัวข้อการตรวจสอบ (Verification Topic) | สถานะ (Status) | หลักฐานในโค้ด (Code Evidence) | สิ่งที่พิสูจน์ได้จริง (Verified Fact) | สิ่งที่เป็นข้อจำกัด / ข้ออนุมาน (Caveat / Assumption) |
| :--- | :---: | :--- | :--- | :--- |
| **1. การต่อภาพแชทและตัดรอยซ้ำ (Chat Stitching & De-overlapping)** | 🟢 **พบหลักฐานรองรับ** | `build_master_transcript.py` (ฟังก์ชัน `parse_chat_stream`), `build_ssot_viewer.py` (MD5 Hash map) | ตัดไฟล์ภาพซ้ำ 100% ได้จริง 194 ไฟล์ และตัดบรรทัดแชทซ้ำข้ามภาพด้วย Buffer ได้จริง | การเรียงลำดับยังพึ่งพาชื่อไฟล์ (Natural Sort) หากชื่อไฟล์ไม่เรียงตามเวลา ลำดับภาพจะคลาดเคลื่อน |
| **2. การย้อนจากรายงานไปพิกัดบนภาพต้นฉบับ (Coordinate Reverse-Lookup)** | 🟢 **พบหลักฐานรองรับ** | `generate_all_focal_points.py`, `SSOT_FOCAL_POINTS_577.json`, `MASTER_SSOT_STITCH_VIEWER.html` (`data-focal-y` + `autoScrollBox`) | คลิกปุ่มส่องประเด็นแล้ววิวพอร์ตวิ่งไปยังพิกัดแกน Y ของบับเบิ้ลเกิดเหตุได้จริงทั้ง 577 โหนด | พิกัดเป็น Scroll Offset ระดับคอนเทนเนอร์ (Y-Pixel) ยังไม่ใช่ Bounding Box อิสระ 4 จุด (x1, y1, x2, y2) |
| **3. การจับคู่แชทกับสลิปแบบ 1:1 (Chat-to-Slip 1:1 Matching)** | 🟡 **พบเพียงข้อความกล่าวอ้าง** | `agent3_forensic_linguistics_miner.py` (อาร์เรย์ `smoking_gun_catalog`), `EVIDENCE_COUNTS_30.json` | มีการ์ดพยานและจุดตายจับคู่แชทกับสลิป 8 จุดในรายงานปลายทาง | **เกิดจากการจัดเตรียมข้อมูลล่วงหน้าโดยมนุษย์ (Human Curated)** ในโค้ด Python ไม่มีอัลกอริทึมที่ดึงยอด/เวลาจากแชทไปสแกนหาสลิปในโฟลเดอร์อัตโนมัติ |
| **4. การสร้าง Timeline 11D จากข้อมูลจริงโดยอัตโนมัติ (Automated 11D Timeline)** | 🟡 **พบเพียงข้อความกล่าวอ้าง** | `extract_static_counts.py`, `build_court_dossier_smart_cropped.py` (อาร์เรย์ `counts = [...]`), `agent5_chronological_11d_timeline.py` | โครงสร้าง 11 มิติถูกสร้างเป็น JSON และ HTML สวยงามครบ 30 กรรม | **ข้อมูล 30 กรรมตั้งต้นถูก Hardcode ไว้ในโค้ด** สคริปต์ Agent 5 ทำหน้าที่เป็นตัวแปลง Template (Formatter/Enricher) มิใช่ตัวสกัดเหตุการณ์อัตโนมัติจากแชทดิบ |
| **5. การแยกบัญชีผู้รับกับการกันนับยอดซ้ำ (Beneficiary & Anti-Double-Counting)** | 🟢 **พบหลักฐานรองรับ (บางส่วน)** | `agent2_slip_miner.py` (การกรองบัญชีโอนคืน `XXX-X-XX452-9` และคัดแยก `has_slip: false`) | กรองบัญชีของเหยื่อออก และกันภาพแชทที่ไม่มีสลิปออกจากยอดเงินได้จริง | การจำแนกผู้รับพึ่งพาตารางบัญชีที่ทราบล่วงหน้า (`KNOWN_ACCOUNTS`) และคีย์เวิร์ดในชื่อไฟล์ (เช่น 'พี่แมว') หากเจอบัญชีใหม่ระบบจะจัดหมวดเป็น 'ไม่ระบุ' |
| **6. การส่งออกเอกสารและลิงก์ภาพต้นฉบับ (Document Export & Image Linking)** | 🟢 **พบหลักฐานรองรับ** | `agent6_president_supreme_court.py`, `EXHIBIT_GENERATOR_DATA.json`, ไฟล์ `COUNT_01..30_RESPONSIVE.html` | มีไฟล์เอกสารมาตรฐาน A4 300 DPI พร้อมหมายเลขคดี หมาย จ.๑ ถึง จ.๓๐ ลิงก์ไปยังภาพตัดหลักฐาน | ไฟล์ภาพหลักฐานที่ฝังใน HTML ถูกก๊อปปี้ไปยังโฟลเดอร์ Asset ปลายทาง ทำให้เปิดดูได้โดยไม่ต้องต่อเน็ต |

## 2. สิ่งที่พิสูจน์ได้ vs สิ่งที่เป็นข้ออนุมาน vs สิ่งที่ยังไม่ทราบ

### 1. สิ่งที่พิสูจน์ได้ (Empirically Proven):
- มีไฟล์ภาพต้นฉบับและแคช OCR ของแชท 106 ภาพ และสลิป 143 ภาพจริง
- การตัดไฟล์ซ้ำด้วยค่า MD5 Hash ทำงานได้แม่นยำ 100% บนชุดข้อมูลทดสอบ
- ระบบพิกัด Scroll Y-Axis เพื่อเลื่อนดูภาพแชทยาว (577 โหนด) ทำงานได้จริงในเบราว์เซอร์
- สคริปต์ Agent 2 สามารถอ่านเลข Ref และยอดเงินจากสลิปธนาคารมาตรฐาน (TTB, KTB, SCB, KBANK) ได้จริง

### 2. สิ่งที่เป็นข้ออนุมาน (Engineering Assumptions / Caveats):
- **สมมติฐานเรื่องชื่อไฟล์:** สายพานหลายจุดสมมติว่าชื่อไฟล์มีข้อมูลลำดับเวลา (เช่น `01.9.68_...`, `LINE_capture_...`) หากไฟล์ภาพนำเข้าเป็นชื่อสุ่มแบบ GUID หรือ Hash สายพานจะเรียงลำดับเวลาไม่ได้
- **สมมติฐานเรื่องบัญชีที่รู้จัก:** สมมติว่าเลขบัญชีปลายทางอยู่ในกลุ่มจำเลยที่ทราบตัวตนแล้ว (`KNOWN_ACCOUNTS`) หากนำไปใช้กับคดีอื่นที่มีผู้ต้องสงสัยกลุ่มใหม่ ต้องแก้ไขโค้ด Python เพื่อเพิ่มเลขบัญชีใหม่

### 3. สิ่งที่ยังไม่ทราบ / ขาดข้อมูล (Unknowns & Missing Pipeline Links):
- **ขาดการเชื่อมโยงอัตโนมัติระหว่าง Agent 1 ➔ Agent 5:** ยังไม่พบโค้ดที่สามารถแปลงผลลัพธ์จาก OCR แชทของ Agent 1 ไปเป็นรายการ 30 กรรมของ Agent 5 ได้โดยตรงโดยไม่ต้องผ่านการคัดเลือกและพิมพ์เนื้อความโดยมนุษย์
- **ขาดฐานข้อมูลความสัมพันธ์เชิงเวกเตอร์แท้ (Vector DB):** แม้ไฟล์และแดชบอร์ดจะใช้ชื่อว่า `VECTOR_EVIDENCE` หรือ `CHAT_FORENSIC_VECTOR_EXPLORER` แต่ในโค้ดเป็นการค้นหาด้วย Keyword Matching (Regex) ธรรมดา ยังไม่มีการใช้งาน Vector Embeddings หรือ Vector Database เช่น ChromaDB, Pinecone, หรือ FAISS ในสคริปต์ชุดนี้
