## 🔍 2. วิธีการอ่านและตรวจสอบชุดตัวอย่าง (How to Trace the Evidence)

ผู้ประเมินสามารถตามรอยหลักฐานจากภาพต้นฉบับไปยังผลลัพธ์ปลายทางได้ตามลำดับดังนี้:

### ตัวอย่างที่ ๑: กรณีแชทข้อความขอยืมเงิน ➔ พิกัดวิวพอร์ต (Node 1 / Count 1)
1. ดูภาพต้นฉบับ: `samples/LINE_capture_800252756.687906.jpg` (SHA-256: `17c47bc...`)
2. ตรวจสอบผล OCR ดิบ: ใน `samples/SAMPLE_INTERMEDIATE_DATA.json` ➔ `chat_ori_cache`
3. ตรวจสอบพิกัดการเลื่อนดู: ใน `samples/SAMPLE_INTERMEDIATE_DATA.json` ➔ `ssot_focal_points` โหนด 1 (พิกัด Y = 2280 px)
4. ตรวจสอบผลการจัดทำสำนวนคดี: ใน `samples/SAMPLE_INTERMEDIATE_DATA.json` ➔ `counts_data` (กรรมที่ ๑)
5. เปิดหน้าแสดงผลจริง: เปิดไฟล์ `EDOK_NUI/COUNT_01_RESPONSIVE.html` ในเบราว์เซอร์

### ตัวอย่างที่ ๒: กรณีสลิปธุรกรรมสมบูรณ์ (Matched Slip Record)
1. ดูภาพสลิป: `samples/01.9.68_IMG_6288.PNG` (SHA-256: `548d5ef...`)
2. ตรวจสอบผลการสกัดของ Agent 2: ใน `samples/SAMPLE_INTERMEDIATE_DATA.json` ➔ `beneficiary_transaction_records`

## ⚠️ 3. ข้อจำกัดและข้อควรระวังสำคัญ (Critical Limitations)

1. **ห้ามถือว่าระบบทำงานอัตโนมัติ 100%:** จากการตรวจสอบโค้ดพบว่า การร้อยเรียง 30 กรรมใน Agent 5 และการจับคู่จุดตาย SG-01..08 ใน Agent 3 **เกิดจากการจัดเตรียมข้อมูลล่วงหน้าโดยมนุษย์ (Human Curated / Pre-baked Data)** แล้วใช้สคริปต์แปลงเป็น Template มิใช่อัลกอริทึมที่จับคู่แชทกับสลิปแบบ 1:1 ได้เองโดยสมบูรณ์
2. **การอิงลำดับจากชื่อไฟล์:** การต่อภาพแชทขนาดยาวและการจับคู่เวลา ยังพึ่งพาชื่อไฟล์ที่เรียงตามลำดับเวลา (Natural Sort)
3. **การรักษาข้อมูลส่วนบุคคล (PDPA / Confidentiality):** ข้อมูลในตัวอย่างนี้แสดงเลขบัญชีแบบ Masked (`XXX-X-XX996-5`) ตามที่ปรากฏในระบบต้นทาง เพื่อความปลอดภัยและเป็นไปตามกฎหมายคุ้มครองข้อมูลส่วนบุคคล
