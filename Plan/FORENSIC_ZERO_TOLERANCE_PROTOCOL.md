# FORENSIC ZERO-TOLERANCE PROTOCOL
**กฎบัตรมาตรฐานความจริงทางนิติวิทยาศาสตร์ดิจิทัลขั้นสูงสุด (Pure Truth & Zero-Hallucination Standard)**  
*มีผลบังคับใช้ถาวรทันทีนับจากนี้เป็นต้นไป ครอบคลุมทุกโมดูล สคริปต์ รายงาน และการส่งมอบงานคดี*

---

## 1. วัตถุประสงค์ (Core Objective)
เพื่อขจัดปัญหาข้อมูลหลอกตา (Hallucination), การนำเข้าข้อมูลตัวอย่าง (Mock Data) มาปะปนกับข้อเท็จจริง และการอนุมานยอดเงินหรือวันเวลาโดยไม่มีพยานหลักฐานรองรับ เพื่อให้สำนวนคดีและรายงานการวิเคราะห์ทุกชิ้นสามารถใช้เป็นพยานหลักฐานที่ชอบด้วยกฎหมายในชั้นศาลตาม ป.วิ.อ. และมาตรฐาน ISO/IEC 27037

---

## 2. กฎเหล็ก 3 ประการ (The 3 Immutable Laws)

### กฎข้อที่ 1: ห้ามใช้ Mock Text หรือสมมุติยอดเงินเองเด็ดขาด (Zero-Mock Law)
* หากไฟล์ภาพใดตรวจสอบแล้ว **ไม่ปรากฏยอดเงิน เลขบัญชี หรือวันเวลาที่เกี่ยวข้องทางการเงิน** ระบบต้องบันทึกค่านั้นเป็น `null` (`NOT_FOUND`) ทันที
* **ห้ามแอบเติมคำ ห้ามคาดเดา ห้ามสร้างข้อความตัวอย่างแม้เพื่อการทดสอบ UI**
* เมื่อไม่มียอดเงินในแชท สถานะการเชื่อมโยงกับสลิปต้องถูกล็อกเป็น **`UNMATCHED`** ทันที และห้ามนำไปรวมยอดความเสียหายแห่งคดีเด็ดขาด

### กฎข้อที่ 2: การตรวจสอบพยานหลักฐานจริง 100% (Strict Grounding Law)
* ทุกข้อความ ตัวเลข ยอดเงิน เลขบัญชี และเวลา ที่นำไปแสดงในรายงาน (Report), JSON SSOT, หรือหน้าจอ UI Dashboard **ต้องถูกสกัด (Extracted) ออกมาจากไบนารีและพิกเซลของภาพจริงผ่านโมเดล OCR เท่านั้น**
* ทุก Entity ต้องมีหลักฐานแหล่งที่มา (Provenance Traceability) ระบุ:
  1. `source_file` (ชื่อไฟล์ต้นฉบับ)
  2. `sha256` (ค่าแฮชของไฟล์ดิบ)
  3. `bbox` (พิกัด Y-min, Y-max, X-min, X-max บนภาพจริง)

### กฎข้อที่ 3: เกณฑ์การส่งมอบงานคดีส่งศาล (Court Evidentiary Standard)
* การจัดทำสำนวนคดีส่งฟ้องหรือเสนอพนักงานสอบสวน **จะต้องใช้เฉพาะข้อมูลที่ผ่านการยืนยันจากภาพที่มีพยานหลักฐานทางการเงินจริงเท่านั้น**
* ตัวอย่างหลักฐานที่ชอบด้วยเกณฑ์:
  - `chatv3 (41).jpg`: ปรากฏเลขบัญชีกสิกรไทย `2050262591` บัญชี ปรียาฉัตร พิกัด `Y: [750 - 1250]`
  - `chatv3 (31).jpg`: ปรากฏข้อมูลบัญชี วันวิสา
  - `chatv3 (42).jpg`: ปรากฏข้อมูลบัญชี พร้อมเพย์ / ออมสิน
* หากภาพใดเป็นเพียงการสนทนาทั่วไป (เช่น `chatv3 (1).jpg`) ให้จัดหมวดหมู่เป็น `NON_FINANCIAL_DIALOGUE` และห้ามผูกเข้ากับสลิปโอนเงินใดๆ ทั้งสิ้น

---

## 3. กลไกการตรวจสอบอัตโนมัติ (Automated Gatekeeping & Enforcement)
* ทุกสคริปต์ในระบบต้องรันฟังก์ชัน `verify_grounding_integrity(entity)` ก่อนบันทึกลง SSOT หากพบข้อความที่ไม่มี Bounding Box และไม่มีผลลัพธ์ OCR จากไฟล์ต้นฉบับ ให้ระงับการทำงาน (Hard Fail) ทันที
