> **สถานะรวม:** 🟡 อยู่ระหว่างวางสเปกและเตรียมพร้อม (Planning & Architecture Staged)  
> **อ้างอิงหัวข้อ:** การแก้ปัญหาน้ำหนักไฟล์ภาพ และเทคนิคป้องกันไม่ให้ 2 เลเยอร์ตีกันหรือแย่งงานกัน

## 🎯 1. วัตถุประสงค์และเป้าหมาย (Objective)
1. **ลดภาระน้ำหนักไฟล์ (Storage & Memory Optimization):** เปลี่ยนผ่านจากการโหลดภาพ PNG/JPEG ขนาดใหญ่ มาใช้ `.WebP` บีบอัดระดับ 80–85% ซึ่งลดขนาดไฟล์ลงได้ 75% – 90% โดยเนื้อหาหลักฐานไม่ผิดเพี้ยน
2. **รักษาความบริสุทธิ์ของพยานหลักฐาน (Forensic Integrity):** ไม่เขียนทับหรือดัดแปลงพิกเซลของภาพต้นฉบับ แยกชั้นการวาดกรอบส่องประเด็นออกจากตัวภาพอย่างสิ้นเชิง
3. **ผสานเลเยอร์ไร้รอยต่อ (Zero Collision):** กำหนดมาตรฐานโค้ดที่ทำให้ชั้นภาพถ่าย (WebP) และชั้นกรอบส่องประเด็น (Vector SVG) ทำงานร่วมกันได้โดยไม่ตีกัน ไม่บัง และไม่แย่งเมาส์

---

## 🧱 2. เสาหลักทางเทคนิค (Core Technical Pillars)

### กฎข้อที่ 1: ล็อกตำแหน่งระนาบ 100% (Plane Synchronization)
* **กลไก:** ใช้ `position: relative` ที่กล่อง Container แม่ และใช้ `position: absolute; top: 0; left: 0; width: 100%; height: 100%;` ที่เลเยอร์ Vector SVG
* **ผลลัพธ์:** สั่งให้กรอบเวกเตอร์ลอยทับอยู่บนระนาบเดียวกันกับภาพเป๊ะๆ กว้าง 100% สูง 100% เท่ากัน ไม่เลื่อนหลุดตำแหน่งแม้หน้าจอจะเปลี่ยนขนาด

### กฎข้อที่ 2: วัตถุล่องหนต่อการคลิก (Click Transparency)
* **กลไก:** บังคับใช้คำสั่ง CSS `pointer-events: none;` บนเลเยอร์กรอบเวกเตอร์
* **ผลลัพธ์:** กรอบสีแดงจะกลายเป็น "วัตถุล่องหนต่อการคลิก" คือเมื่อผู้ใช้เอาเมาส์ไปจิ้ม เลื่อน แพน หรือซูมภาพ นิ้วหรือเมาส์จะทะลุผ่านกรอบสีแดงลงไปจับที่ภาพด้านล่างได้ทันที กรอบจะไม่ขวาง ไม่แย่งเมาส์ และไม่ทำให้เบราว์เซอร์กระตุก

### กฎข้อที่ 3: ระบบพิกัดสัมพัทธ์ (Normalized Relative Coordinates)
* **กลไก:** บันทึกพิกัดกรอบบับเบิ้ลเป็นสัดส่วนเปอร์เซ็นต์ $(0.0 - 1.0)$ แทนพิกเซลสัมบูรณ์
* **ผลลัพธ์:** สเกลกรอบสีแดงตรงกับบับเบิ้ลข้อความแชท 100% ในทุกระดับการย่อ/ขยายหน้าจอ
