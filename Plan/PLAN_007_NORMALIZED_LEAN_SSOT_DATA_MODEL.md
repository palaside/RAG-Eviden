# 📑 แผนงาน PLAN-007: โครงสร้างข้อมูลไม่บวมระดับศูนย์กลาง (Normalized Lean SSOT Data Model)

> **รหัสแผน:** `PLAN-007`  
> **วันที่สร้าง:** 22 พฤศจิกายน 2026  
> **สถานะรวม:** 🟡 อยู่ระหว่างวางสเปกและเตรียมพร้อม (Planning & Architecture Staged)  
> **อ้างอิงหัวข้อ:** การจัดระเบียบฐานข้อมูล Single Source of Truth ไม่ให้บวม ลดขนาดไฟล์ข้อมูลจาก 50MB เหลือ 1-2MB

---

## 🎯 1. วัตถุประสงค์และเป้าหมาย (Objective)
1. **กำจัดความซ้ำซ้อนของข้อมูล 100% (Zero Redundancy):** แยกข้อมูลบุคคล, บัญชีธนาคาร, สลิป, และข้อความแชท ออกเป็นตารางความสัมพันธ์ (Relational Entities) แทนการก็อปปี้ข้อความยาวๆ ซ้ำๆ
2. **บีบอัดขนาดไฟล์ลงกว่า 90% (Lean Payload):** ทำให้ไฟล์ข้อมูลทั้งคดีมีขนาดเพียง 1–2 MB โหลดขึ้นหน่วยความจำได้ในพริบตา
3. **รักษาความสอดคล้องของข้อมูลทั่วทั้งระบบ (Strict Data Integrity):** หากมีการแก้ไขหรืออัปเดตข้อมูลบุคคลที่จุดเดียว ทุกหน้าแดชบอร์ด (SSOT, บุคคล, ไทม์ไลน์, สำนวนฟ้อง) จะอัปเดตตรงกันทันที

## 🗄️ 2. โครงสร้างข้อมูลแบบ Normalized (Relational Schema)

```
┌─────────────────┐       ┌─────────────────┐
│     Persons     │       │    Accounts     │
│  (ข้อมูลบุคคล)    │◀──────│  (บัญชีธนาคาร)   │
├─────────────────┤ 1   * ├─────────────────┤
│ id              │       │ id, person_id   │
│ full_name, role │       │ bank, acc_no    │
└────────┬────────┘       └────────┬────────┘
         │ 1                       │ 1
         │                         │
         │ *                       │ *
┌────────┴────────┐       ┌────────┴────────┐
│  Chat Bubbles   │       │   Bank Slips    │
│  (บับเบิ้ลแชท)   │       │   (สลิปการเงิน)  │
├─────────────────┤       ├─────────────────┤
│ id, image_id    │       │ id, ref_id      │
│ sender_id       │       │ amount, datetime│
│ text, box, time │       │ from_acc, to_acc│
└────────┬────────┘       └────────┬────────┘
         │                         │
         └───────────┬─────────────┘
                     ▼
         ┌─────────────────────────┐
         │     Timeline Events     │
         │    (เหตุการณ์คดี 11D)    │
         ├─────────────────────────┤
         │ event_id, count_no      │
         │ bubble_id, slip_id      │
         │ legal_dimension, focal  │
         └─────────────────────────┘
```

### หลักการออกแบบเพื่อความไม่บวม (Anti-Bloat Principles):
* **ID Mapping:** ทุกความสัมพันธ์อ้างอิงด้วยรหัสสั้น (เช่น `P01`, `ACC02`, `B145`) แทนการใส่ชื่อเต็มซ้ำทุกบรรทัด
* **Shared Lookup Tables:** ธนาคาร, บทบาทบุคคล, และข้อหาทางกฎหมาย ถูกเก็บเป็นตารางอ้างอิงกลาง (Code Table)
* **Separation of Media & Metadata:** ข้อมูลตัวเลขและพิกัดถูกแยกออกจากเนื้อหาภาพดิบอย่างเด็ดขาด
