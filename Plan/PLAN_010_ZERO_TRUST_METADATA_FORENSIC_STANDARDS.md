## 🎯 1. วัตถุประสงค์และเป้าหมาย (Objective)
1. **สถาปนากฎ Zero-Trust Metadata ในคดีความ:** ไม่ยอมรับชื่อไฟล์หรือวันที่ของระบบไฟล์ (Windows/Exif) เป็นข้อเท็จจริงทางคดีเด็ดขาด เพราะสามารถดัดแปลงได้ง่าย
2. **พิสูจน์ความแท้จริงของเวลาด้วย 4 เสาค้ำยัน (4-Pillar Verification):** สอบยันเวลาในแชทกับแถบสถานะหัวจอโทรศัพท์ และสมอยึดธนาคาร (Bank Anchor) เพื่อไม่ให้ฝ่ายตรงข้ามคัดค้านได้
3. **ดักจับภาพแชทปลอมและรอยตัดต่อ (Fake Chat & ELA Forensics):** ใช้เทคนิค Error Level Analysis และการวิเคราะห์ฟอนต์เพื่อชี้ชัดว่าภาพถูกดัดแปลงข้อความหรือตัวเลขหรือไม่

## 🏛️ 2. ลำดับชั้นความน่าเชื่อถือแห่งพยานหลักฐาน (Hierarchy of Trust)

## 🛡️ 3. เสาค้ำยัน 4 ประการในการพิสูจน์เวลาแท้ (4-Pillar Forensic Verification)

### เสาที่ 1: ตรวจสอบความสอดคล้องของหัวจอ (Status Bar Correlation)
* **นาฬิกาหัวจอ vs เวลาบับเบิ้ล:** ตรวจสอบความสัมพันธ์ระหว่างเวลานาฬิกาบน Status Bar หัวจอกับเวลาในบทสนทนา (หากแชทบอก 15:00 น. แต่นาฬิกาหัวจอเขียน 09:15 น. ➔ ถือว่าขัดแย้ง/ดัดแปลง)
* **ระดับแบตเตอรี่:** ตรวจสอบความต่อเนื่องของการลดลงของระดับแบตเตอรี่ในแต่ละภาพต่อเนื่อง

### เสาที่ 2: ผูกตรึงเวลากับ "สมอยึดธนาคาร" (External Bank Anchor)
* สลิปธนาคารและ Statement จากธนาคารคือจุดยึดเหนี่ยวที่มั่นคงที่สุด
* เมื่อแชทมีการพูดคุยเรื่องโอนเงิน ณ เวลา $T$ และมีสลิปแนบที่มี Ref ID และวันเวลา $T$ ตรงกับ Statement ➔ ให้ประทับตรา **`[✅ TIME-LOCKED BY BANK]`** ทันที

### เสาที่ 3: ตรวจสอบลำดับเวลาเชิงเส้น (Chronological Monotonicity)
* เวลาในคดีจริงต้องเดินไปข้างหน้าเสมอ ($t_1 \le t_2 \le t_3$)
* หากพบบับเบิ้ลหรือเหตุการณ์ที่เวลากระโดดย้อนกลับ ระบบจะติดแท็กเตือนสีแดง:  
  *`[🚩 TIME CONFLICT / NON-MONOTONIC: ตรวจพบเวลาเดินย้อนกลับ]`*

### เสาที่ 4: นิติวิทยาศาสตร์เนื้อภาพและฟอนต์ (Image Forensics & Font Metrics)
* **Error Level Analysis (ELA):** ตรวจจับรอยต่อและระดับคลื่นการบีบอัด JPEG บริเวณตัวเลขยอดเงินและเวลา หากมีการตัดแปะตัวเลข ค่า ELA จะฟ้องความแตกต่างทันที
* **Font Metric Check:** ตรวจสอบระยะห่างวรรณยุกต์ (Kerning/Leading) และหัวพยัญชนะไทย เทียบกับมาตรฐาน Native Rendering ของแอป LINE

## 📋 4. รายการสิ่งที่ต้องทำ (To-Do List & Progress Tracking)

### ระยะที่ 1: การกำหนดเกณฑ์และแท็กสถานะพยานหลักฐาน (Forensic Tagging Schema)
- [x] ✅ ถอดบทเรียนกฎ Zero-Trust Metadata และโครงสร้างความน่าเชื่อถือ 3 ระดับลงเอกสาร
- [ ] กำหนดระบบแท็กสถานะหลักฐาน: `[UNVERIFIED]`, `[CORROBORATED]`, `[TIME-LOCKED]`, `[CONFLICT]`
- [ ] พัฒนาโมดูลตัดขาดชื่อไฟล์ออกจากตรรกะการตัดสินลำดับเวลา (Decouple Filename from Chronology)

### ระยะที่ 2: การพัฒนาตัวตรวจจับความสอดคล้อง (Corroboration Engine)
- [ ] พัฒนาตัวอ่านและเปรียบเทียบนาฬิกาบน Status Bar หัวจอ กับเวลาในแชทบับเบิ้ล
- [ ] พัฒนาตัวเชื่อมโยงสลิปธนาคารเข้ากับบับเบิ้ลแชทเพื่อล็อกเวลา (Bank Anchor Locker)
- [ ] พัฒนาระบบตรวจจับเวลาเดินย้อนกลับ (Chronological Monotonicity Validator)

### ระยะที่ 3: ระบบตรวจจับรอยตัดต่อ (Image Forgery & ELA QA)
- [ ] พัฒนาโมดูลสแกน Error Level Analysis (ELA) วิเคราะห์รอยแตกของพิกเซลรอบตัวเลข
- [ ] สร้างรายงานรับรองความบริสุทธิ์ของพยานหลักฐาน (Digital Evidence Authenticity Report) ส่งศาล
